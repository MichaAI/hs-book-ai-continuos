# Функтор

Мы теперь умеем строить этажи нашего типового небоскрёба (конструкторы типов) и умеем наделять типы способностями (классы типов). Пора соединить эти два умения воедино. И начнём мы с одной досадной, но чрезвычайно распространённой проблемы.

## Одна и та же боль

Вспомним нашу функцию поиска главы по пути:

```haskell
lookupChapterNameBy :: FilePath -> Chapters -> Maybe String
```

На выходе &mdash; опциональная строка. И вот нам понадобилось эту строку как-то преобразовать, скажем, перевести все символы в верхний регистр:

```haskell
import Data.Char (toUpper)

shout :: Maybe String -> Maybe String
shout Nothing     = Nothing
shout (Just name) = Just (map toUpper name)
```

Работает исправно, но взгляните на этот паттерн: если внутри `Nothing` &mdash; ничего не делаем, оставляем `Nothing`; если внутри `Just` &mdash; аккуратно достаём значение, применяем к нему функцию, заворачиваем результат обратно в `Just`. Знакомо? Ещё бы, мы такое уже писали не раз. А теперь представим, что нам нужно сделать то же самое, но для списка:

```haskell
shoutAll :: [String] -> [String]
shoutAll names = map (map toUpper) names
```

Тут нам, к счастью, помогает `map` &mdash; она сама умеет пробегать по списку и применять функцию к каждому элементу. Но что если у нас список, обёрнутый в `Maybe`? А `Either String Int`? А наш собственный тип `IPAddress`, внутри которого мы вдруг захотели что-то поменять? Получается, для каждого этажа нашего небоскрёба приходится заново и заново писать один и тот же по духу код: &laquo;спустись на этаж, возьми значение, примени функцию, снова поднимись на тот же этаж&raquo;.

```
       Maybe String              [String]

        Just name                [n1, n2, n3]
           |                          |
    достать значение          достать значения
           |                          |
     применить f                применить f к каждому
           |                          |
      Just (f name)            [f n1, f n2, f n3]

    один и тот же по духу процесс, но разный код
```

Раз уж мы научились в прошлой главе распознавать общие способности типов и выражать их через классы типов, самое время задать вопрос: а нет ли здесь общей способности, которую можно выделить один раз и переиспользовать для любого этажа?

## Класс Functor

Есть, и называется она `Functor`. Вот её определение из стандартной библиотеки, я слегка его упростил:

```haskell
class Functor f where
    fmap :: (a -> b) -> f a -> f b
```

Обратите внимание на тонкость: типовая заглушка здесь &mdash; не сам тип, а конструктор типа `f`. Прошлая глава научила нас, что `f` тут &mdash; это как раз то, что порождает наши этажи: `Maybe`, `[]` (сокращённая запись для списочного конструктора), `Either String` и так далее.

Функция `fmap` (сокращение от &laquo;functorial map&raquo;) берёт обычную функцию `a -> b` и обычную функцию превращает в функцию, работающую &laquo;прямо на этаже&raquo;, не заставляя нас спускаться:

```haskell
fmap :: (a -> b) -> f a -> f b

        обычная      значение на    результат
        функция      этаже f        всё ещё на этаже f
```

Определим представителя `Functor` для `Maybe`:

```haskell
instance Functor Maybe where
    fmap _ Nothing  = Nothing
    fmap f (Just x) = Just (f x)
```

И теперь наша функция `shout` пишется одной строкой, без всякого паттерн матчинга:

```haskell
shout :: Maybe String -> Maybe String
shout = fmap (map toUpper)
```

А как насчёт списков? Тут всё ещё проще, ведь `Functor` для списка &mdash; это буквально то же самое, что и старая добрая `map`:

```haskell
instance Functor [] where
    fmap = map
```

И вот наблюдение, которое я нахожу по-настоящему красивым: если `fmap` для списка &mdash; это `map`, то, значит, `map` всё это время была частным случаем куда более общей операции. Мы просто не видели общей картины, пока не выучили классы типов.

## Инфиксный fmap

`fmap` настолько часто применяется, что для неё определён инфиксный оператор-синоним, `<$>`:

```haskell
(<$>) :: Functor f => (a -> b) -> f a -> f b
(<$>) = fmap
```

Перепишем `shout`:

```haskell
shout :: Maybe String -> Maybe String
shout maybeName = map toUpper <$> maybeName
```

Символ `<$>` неспроста напоминает нам про `$` &mdash; оператор применения функции, с которым мы познакомились ещё в главе про операторы. И это не случайность: `<$>` можно воспринимать как &laquo;применение функции, которое умеет проникать сквозь этаж&raquo;. Обычный `$` применяет функцию к голому значению, а `<$>` &mdash; к значению, упрятанному в `Maybe`, список, или любой другой функтор.

```haskell
                f  $   x   -- обычное применение

               f <$>  fx   -- применение сквозь этаж f
```

## Функтор двигает, но не покидает этаж

Присмотримся к сигнатуре ещё раз, теперь особенно внимательно:

```haskell
fmap :: (a -> b) -> f a -> f b
```

На входе &mdash; значение на этаже `f`, и на выходе &mdash; тоже значение на этаже `f`. Это принципиально: `fmap` никогда не меняет этаж, на котором находится значение. Если у нас был `Maybe String`, после `fmap` мы получим `Maybe <что-то>`, но не `Int`, не `IO String`, не что-либо ещё. `fmap` меняет лишь содержимое этажа, но не сам этаж. Хорошая аналогия: `fmap` &mdash; это как приказать всем жителям этажа сделать одно и то же упражнение, не пуская никого ни вверх, ни вниз по лестнице.

Это и есть суть функтора: контейнер (в широком смысле, этаж), внутри которого можно применить функцию, не покидая контейнер и не разрушая его структуру. Слово &laquo;структура&raquo; здесь ключевое: если у нас был список из трёх элементов, после `fmap` мы получим список тоже из трёх элементов, просто с гипотетически другими значениями внутри. Если было `Nothing`, оно так и останется `Nothing` &mdash; функция `f` попросту не будет вызвана, ведь внутри нечего преобразовывать.

## Ещё несколько представителей

Наш собственный тип `IPAddress` тоже может стать функтором, хотя тут придётся слегка обобщить его определение, добавив типовую заглушку:

```haskell
data Box a = Box a

instance Functor Box where
    fmap f (Box x) = Box (f x)
```

```haskell
Prelude> fmap (+1) (Box 41)
Box 42
```

А вот тип `Either e`, который вы наверняка встретите в реальном Haskell-коде, тоже функтор, но с любопытной особенностью:

```haskell
instance Functor (Either e) where
    fmap _ (Left err) = Left err
    fmap f (Right x)  = Right (f x)
```

Заметьте: конструктор `Left` игнорируется точно так же, как `Nothing` в случае `Maybe`. Это неспроста: `Either e a` часто используется для представления вычислений, которые могут либо завершиться ошибкой (`Left`, внутри &mdash; описание ошибки типа `e`), либо успехом (`Right`, внутри &mdash; полезный результат типа `a`). `fmap` для `Either` красноречиво говорит нам: &laquo;если была ошибка &mdash; преобразовывать нечего, ошибка так и останется ошибкой; а вот если был успех &mdash; применим функцию к результату&raquo;.

```haskell
Prelude> fmap (*2) (Right 21 :: Either String Int)
Right 42
Prelude> fmap (*2) (Left "boom" :: Either String Int)
Left "boom"
```

Обратите внимание на ту деталь, что конструктор `Either` принимает *два* типовых параметра, `e` и `a`, но представителем `Functor` становится `Either e`, а не сам по себе `Either`. Это важно: класс `Functor` требует конструктор типа, который принимает ровно один параметр &mdash; ведь именно этот, последний, параметр и подвергается преобразованию функцией `f`. `e` в `Either e a` как бы &laquo;зафиксирован&raquo; и в `fmap` не участвует.

## Законы функтора

Не любое определение `fmap`, которое компилируется, действительно достойно называться функтором. Существует негласный (точнее, не проверяемый компилятором, но обязательный по соглашению) контракт &mdash; законы функтора.

Первый закон, закон тождества:

```haskell
fmap id = id
```

Если мы применим `fmap` к функции `id` (напомню, `id x = x`, функция, которая просто возвращает свой аргумент без изменений), результат должен быть неотличим от исходного значения. Логично: если мы ничего не меняем внутри этажа, значит, и сам этаж остаётся ровно таким же, каким и был.

Второй закон, закон композиции:

```haskell
fmap (g . f) = fmap g . fmap f
```

Если мы сперва применим композицию двух функций через `fmap`, а затем применим `fmap` дважды подряд с этими же функциями по отдельности, результат обязан совпасть. Иными словами, неважно, объединяем ли мы преобразования до похода на этаж или применяем их одно за другим уже там &mdash; итог один и тот же.

Зачем эти законы вообще нужны, если компилятор их не проверяет? А затем, что они гарантируют предсказуемое поведение. Если бы кто-то определил, скажем, такого &laquo;функтора&raquo;:

```haskell
instance Functor Maybe where
    fmap _ Nothing  = Just какая-то-случайная-фигня  -- Плохо!
    fmap f (Just x) = Just (f x)
```

&hellip;формально код бы скомпилировался, но семантика оказалась бы сломана: `fmap id` перестал бы быть тождественным преобразованием для `Nothing`. Такой код нарушает ожидания любого, кто когда-либо видел слово &laquo;функтор&raquo;, и рано или поздно приведёт к трудноуловимым багам. Хорошая новость: для подавляющего большинства типов существует ровно один разумный способ реализовать `fmap`, и написать его &laquo;плохо&raquo; нужно приложить отдельные усилия.

## Возвращаемся к нашим главам

Вооружившись `Functor`, перепишем функцию, которая ищет главу и сразу переводит её название в верхний регистр, причём сделаем это без единого паттерн матчинга на `Maybe`:

```haskell
shoutChapterNameBy :: FilePath -> Chapters -> Maybe String
shoutChapterNameBy path chs = map toUpper <$> lookupChapterNameBy path chs
```

Функция `lookupChapterNameBy` возвращает `Maybe String`, а `<$>` аккуратно &laquo;пробирается&raquo; внутрь, минуя необходимость ручного разбора конструкторов `Nothing`/`Just`. Если глава не найдена &mdash; результат `Nothing`, и функция `map toUpper` попросту не вызывается. Если найдена &mdash; получаем `Just` с преобразованным именем. Красиво, лаконично, и, что немаловажно, совершенно безопасно: компилятор не даст нам забыть обработать случай отсутствия значения, потому что за нас это уже сделал автор представителя `Functor` для `Maybe`.

## Приоткрывая дверь дальше

Кажется, будто `Functor` решает все наши проблемы с этажами. Но есть один случай, с которым `fmap` справиться не в силах. Представьте: у нас есть не просто значение на этаже, а *функция*, обёрнутая в этот же этаж:

```haskell
Just (+1) :: Maybe (Int -> Int)
```

И есть обычное значение на том же этаже:

```haskell
Just 41 :: Maybe Int
```

Мы хотим применить первое ко второму и получить `Just 42`. Но `fmap` тут бессилен &mdash; её первый аргумент обязан быть *голой* функцией, а не функцией, замурованной внутри `Maybe`:

```haskell
fmap :: (a -> b) -> f a -> f b
              ^
              не Maybe (a -> b), а именно a -> b!
```

Получается, `Functor` умеет применять функцию снаружи этажа к значению на этаже, но не умеет применять функцию, которая сама уже находится на этаже. Для этого нам понадобится способность помощнее. Знакомьтесь: `Applicative`.
